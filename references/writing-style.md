# 中国发明专利 · 行文手法与各部分写法范式

本文件讲"怎么写"——中国发明专利说明书/权利要求书的惯用句式、结构与口吻。例句用**通用占位示例**演示
形式，实际撰写时把"第一处理单元/目标对象/预设阈值"等换成本技术方案的真实要素。目标是让产出读起来像
专利代理人写的正式申请文件。

## 通用口吻
- 用"所述"回指已引入的要素：第一次出现"一缓存队列"，之后一律"所述缓存队列"。
- 用上位、功能性措辞：用"通信通道""存储模块""预设阈值"而非具体品牌/数字（数字留实施例）。
- 客观、陈述、无第一人称（"本发明"除外）；少用形容词，多用"用于…""使得…""从而…"。
- 句子可以长、分号分层；权利要求一项常是"一句话 + 若干分号子句"。
- **数学公式**：正文用 LaTeX 行内写法，装配时自动转为 Word 原生公式（可在 Word 公式编辑器里改）：
  `$E=mc^2$`、`\( x^2+y^2=z^2 \)`、`\[ \sum_{i=1}^{n} x_i \]`；显示公式可用 `$$...$$`。
  勿把公式当纯文本写（如 `x^2` 无 `$` 包裹不会转换）；复杂式子优先 LaTeX，少用 Unicode 上下标凑合。
  **每个关键公式后写「其中 $x$ 为…」**；复杂稿关闭自动公式识别（`AUTO_MATH=False`）。
  若公式声称优化时间偏移、偏置或尺度等变量，必须同时写明该变量如何变换候选数据、如何进入目标函数、
  正负约定、数据来源、无效样本处置，以及目标取最大值或最小值；不能只在公式外的文字中出现。
- **中文优先**：权项与说明书以中文术语为主；公知缩写首次「中文全称（英文缩写）」；禁止未解释英文堆砌。
  动笔前锁定术语表（内部名→专利用语），全文只许表内用词。

## 一、说明书摘要（约 200–300 字，一段）
开头固定"本发明公开了一种……"。一段话讲清：解决什么问题 + 用什么手段 + 达到什么效果。不分点、不放附图标记。

**范式：**
> 本发明公开了一种〔发明名称〕。针对〔现有技术的关键问题，一句话〕，本发明〔核心手段，2–3 个分句串起主
> 流程〕；〔点出最关键的创新机制〕。本发明〔一句话效果/有益结论〕。

## 二、权利要求书
独立权利要求是保护范围的核心，最宽；从属逐层加限定。**所有数值/型号/接口都不写进权利要求**，留给实施例。

**强制：合计 10 条。** 草稿超过 10 条时按 `references/claims-quality.md` **合并**（不是删除创新点）。
默认骨架对齐 `参考模板.docx`：方法独立1 + 从属2–7 + 多引8 + 系统独立9 + 设备/介质10。

### 2.0 用"功能/角色/模式"抽象，求宽保护（核心手法）
能用**功能或角色**描述的技术特征，就不要用**具体产品/型号/实现**描述——后者把保护范围钉死在某一种实现上，
别人换个等效实现就绕开了。把"做什么、起什么作用"写进权利要求，把"用什么做的"留给实施例。
- 反例（过窄，绑死具体实现）：`用〔某具体型号部件〕对〔对象〕做〔处理〕`。
- 正例（按功能抽象，覆盖多种实现）：`以〔第一处理单元〕对〔对象〕执行〔某功能〕，输出〔结果〕`；
  若一个特征可由多种形态实现，**再补一条从属权利要求兜住它们**：
  `所述〔第一处理单元〕与〔第二处理单元〕，由同一装置以不同工作模式承载，或分别由不同装置承载。`
- 边界把握：抽象要"宽而仍清楚"——读者能据说明书理解其含义且实施例有支撑；不可宽到含义不清（会因"得不到说明书支持/不清楚"被驳）。凡权利要求里宽出去的写法，说明书必须给出泛化依据（如上面的兜底从属项）。

### 2.1 独立方法权利要求（claim 1）
固定骨架："1.一种〔名称〕，其特征在于，包括以下步骤：" + 步骤1…N（或 S1…Sn，**全篇统一**）。
把**最硬的创新点写进 claim 1 的步骤里**，不要藏到从属。步骤数 4–7 个为宜，每步一句、分号结尾、末步句号。
只写**必要技术特征**；对解决技术问题无贡献的场景形容词不要塞进独立项。

**范式：**
> 1.一种〔名称〕，其特征在于，包括以下步骤：
> 步骤1：〔获取/接入……〕；
> 步骤2：〔关键处理一，含创新点〕；
> 步骤3：〔关键处理二〕；
> 步骤4：〔输出/决策……〕。

### 2.2 从属权利要求（2–7）
固定开头"N.根据权利要求M所述的方法，其特征在于，〔对某步骤的细化〕："。可对某步展开为若干分句。
把"换序校验、阈值闸门、几何反算、状态机、容错重试、质量评分"等放这里（仍用上位词）。
**若细化点很多：合并进同一条的分号子句，而不是新开第11、12条。**

**范式：**
> 3.根据权利要求1所述的方法，其特征在于，步骤2中所述〔X〕具体包括：
> 〔分句一〕；
> 〔分句二〕。

### 2.3 多引用从属（第8条）
> 8.根据权利要求1至7任一项所述的方法，其特征在于，〔一条贯穿性限定，如"全程以唯一标识为键…"〕。

### 2.4 系统权利要求（第9条，独立）
> 9.一种〔名称〕系统，用于执行如权利要求1至8任一项所述的方法，其特征在于，包括：
> 〔模块A〕，用于〔对应方法步骤〕；
> 〔模块B〕，用于〔…〕。

模块与方法步骤一一呼应。

### 2.5 计算机设备 / 存储介质（第10条）
对齐参考模板常见写法（二选一或按方案择一，仍计为第10条）：
> 10.一种计算机设备，包括存储器和处理器，所述存储器上存储有可在处理器上运行的计算机程序，其特征在于，
> 所述处理器执行所述计算机程序时实现如权利要求1至8任一项所述的方法。

或：
> 10.一种计算机可读存储介质，其上存储有计算机程序，其特征在于，所述程序被处理器执行时实现如权利要求1至8任一项所述的方法。

> 编号连续；引用合法；方法↔系统要素对应。细节与合并规程见 `claims-quality.md`。

## 三、说明书各部分

### 3.1 技术领域（1 句）
> 本发明涉及〔大领域〕及〔具体子领域〕技术领域，具体地涉及一种〔发明名称〕。

### 3.2 背景技术（"现状—缺陷—收束"三段式）
- 先讲现状/已有方案（可分"第一类…第二类…"）。
- 逐一点出每类的**核心缺陷**（误报率高、算力贵、视野受限、网络隔离不通…），这是反衬本发明的支点。
- 固定收束句："因此，如何〔正面表述要解决的问题〕，是当前亟待解决的技术问题。"

> 把本发明最强的两个新颖点，在背景里写成"现有技术做不到的痛点"，效果最好。

### 3.3 发明内容（技术方案叙述 —— 不是第二份权利要求书）

**硬规则：`根据权利要求N所述…` / `1.一种…其特征在于` 这类正式权项句式，只允许出现在「权利要求书」节；发明内容禁止再写一遍正式权利要求。**

参考模板结构（顺序固定）：

1. 目的段：针对现有缺陷，提供一种〔名称〕。
2. 技术解决方案引导句 + **独立方法的步骤概述**（可与 claim1 步骤同义，用陈述句，**不要**加「1.」「权利要求」字样）。
3. 若干「进一步地，……」：对应从属限定的技术展开（陈述句；术语与权项一致，但**不用**「根据权利要求N所述」）。
4. 「另一方面，提供了一种……系统，……包括：」+ 模块列表（对应系统独立项）。
5. **有益效果写在发明内容末尾**，模板句式为：  
   `本发明与现有技术相比，其显著优点为：` + `（1）（2）…`  
   **不要单独开「有益效果」一级标题**（参考模板无此标题）。

> 发明内容是说明书对技术方案的支持性叙述；权利要求书才是保护范围文本。二者术语一致，但体裁不同——前者「进一步地/另一方面」，后者「根据权利要求…」。

为控页数：独立步骤可完整列出；「进一步地」覆盖主要从属即可，勿把实施例里的「具体地/优选数值」提前写进发明内容。

### 3.4 附图说明（每图一句）
固定句式：
> 图N为本发明实施例〔提供的/中……的〕〔图的内容〕示意图；
（最后一图用"……框图。"或"……示例。"）

### 3.5 具体实施方式（对齐参考模板句式；可实施细节主要写在这里）

> 实施例的**数量、类型与顺序由本技术方案决定**。引用附图时图号按实际附图编排。
> **步骤编号与权利要求/发明内容保持一致**（若权项用「步骤S1」则实施例亦用「步骤S1」，勿混用「步骤1」）。

**硬规则（参考模板实测结构，缺一不可）：**

1. **套话起头**（可压缩，勿省略方向性说明）：目的清楚、实施例非限制、第一/第二仅区分等。
2. **方法实施例引导**：  
   `在一个实施例中，结合图〔流程示意图号〕，提供了一种〔名称〕，所述方法包括以下步骤：`
3. **步骤概述清单**：紧接着逐条写出  
   `步骤S1：……；` … `步骤Sn：……。`  
   （与 claim1 / 发明内容同义，便于对照附图；**这是实施方式引导，不是再写正式权利要求**。）
4. **逐步展开（主体篇幅）**：对每一步及重要从属限定，用模板固定句式反复展开——  
   `进一步地，在其中一个实施例中，步骤Sn中……。`  
   → `具体地：……`（公式、参数含义、例如/优选数值、分支条件）  
   → 必要时 `这里需要说明的是，……` 或 `优选地，在一些实施例中，……`。  
   **每一从属权利要求的关键限定，都应在某条「进一步地…步骤Sn中」里落到可实施细节。**
5. **系统 / 设备实施例**：  
   `在一个实施例中，结合图〔架构图号〕，提供了一种……系统，……包括：` 按模块说明；  
   再 `在一个实施例中，提供了一种计算机设备 / 存储介质，……`。
6. **禁止**：实施例中出现「根据权利要求N所述」或「1.一种…其特征在于」整段权项；  
   **禁止**只用「在本步骤中」替代「进一步地，在其中一个实施例中，步骤Sn中」（后者为参考模板主句式）。
7. **篇幅**：具体实施方式应占说明书主要可实施披露；**不得**为控页把实施方式压成「每步一两句」。  
   控页优先砍：发明内容重复、背景灌水、附图凑数；**不砍**「进一步地/具体地」中的必要参数与分支。
   对已有草稿做版式、术语、公式或一致性修订时，先统计「发明内容」和「具体实施方式」的字符数与 `body` 段数；
   未经用户明确同意，不得以整篇重写或控页为由减少上述两章的可实施披露。若必须删除错误内容，
   须用等量、术语一致且更准确的技术展开替代，并在交付时说明。
   用户另给旧版 Word 时，须再逐项比对旧稿的可实施特征是否已在当前权项、发明内容、实施方式和附图中覆盖；
   不可只因篇幅相近即认定未遗漏，也不可把含品牌、文献、代码痕迹或未证实数据的旧段落原样搬回。
8. **AI/模型应用披露（局令第84号 / 指南Ⅱ-9）**：若用检测、分割等预训练模型，须在实施例写清  
   **输入→输出**及与场景的内在关联（例如「检测框作为提示分割与航迹关联的观测输入，而非直接作为点云种子」）；  
   不得仅写「通过神经网络得到结果」。失败分支（降级粗掩膜、丢弃不一致帧、回退纯雷达）一并写明。
9. **启动链与输出链闭合**：每一个种子点集、候选簇、先验或基线均应在首次使用前说明独立生成方式、最小有效条件
   及不可用处置；区分建站/维护标定与在线事件处理，避免“标定依赖掩膜、掩膜又依赖标定”的循环叙述。
   摘要、权项、发明内容、实施例、系统模块和附图中每一个对外输出都应有量测步骤、质量判据、回退来源或无结果处置；
   例如承诺长、宽、高时，三者都要给出相应测量与基线回退，不能只展开前两项。
10. **状态、指标和方向名唯一**：明确区分站点级标定拟合优度与事件级质量评分；预先列出互斥输出状态、判定优先级、
    量测来源和留痕字段。无向主轴的轴向圆均值应称“主轴方位”；只有额外使用运动方向等信息消除180度歧义时才称“航向”。

**范式摘录：**
> 在一个实施例中，结合图1，提供了一种〔名称〕，所述方法包括以下步骤：  
> 步骤S1：〔与权利要求同义的概述〕；  
> ……  
> 进一步地，在其中一个实施例中，步骤S2中所述〔关键机制〕具体为：……。  
> 具体地：采用〔公式〕，其中〔各参数含义〕；优选〔数值〕；当〔条件〕时〔分支〕。  
> 在一个实施例中，结合图2，提供了一种〔名称〕系统，……包括：〔模块〕……。

**反例（禁止）**：在说明书任意位置再次输出  
`1.一种……方法，其特征在于……` / `2.根据权利要求1所述的……` 整段权项文本。

## 四、页数与去重（总页数 ≤45）

成稿（含附图）渲染后页数**不得超过 45 页**。超页时优先砍重复，不砍必要技术披露：

1. **正式权利要求只在权利要求书出现一遍**；发明内容/实施例禁止再粘贴权项原文。
2. 发明内容：步骤概述 +「进一步地」要点；数值与推导向实施例「具体地/优选」。
3. 有益效果控制在发明内容末「显著优点（1）（2）…」，通常 5–9 条，勿再开独立章节重复写。
4. 背景技术点到痛点即可（通常数段）。
5. 附图够用即可；多实施例相同部分互相参见。

## 五、自查清单（写完通读一遍）
- [ ] **全文检索**：`根据权利要求` 与 `其特征在于` 的正式权项句式仅出现在权利要求书节。
- [ ] 权利要求合计 **10 条**；若曾更多，已**合并**而非删除创新点（见 `claims-quality.md`）。
- [ ] 说明书一级标题对齐参考模板：技术领域 / 背景技术 / 发明内容 / 附图说明 / 具体实施方式（**无**独立「有益效果」标题）。
- [ ] 权利要求无具体数值/型号；实施例用「例如/优选」。
- [ ] 术语表锁定；发明内容「进一步地」与权项术语一致但体裁不同。
- [ ] 具体实施方式含：实施例引导 + 步骤清单 + 多段「进一步地，在其中一个实施例中，步骤Sn中」+「具体地」；
      未用「在本步骤中」整章替代模板句式；从属关键限定已落入某步展开。
- [ ] 涉 AI/检测/分割：说明书已写清模型输入—输出及与场景关联（非黑盒一句）；关键公式参数均有「其中…为…」。
- [ ] 每个优化变量在候选数据变换和目标函数中均有显式位置；每个种子/基线有无循环生成方式与不可用处置。
- [ ] 每个输出字段有量测、质量与回退/无结果链；状态优先级、指标名称和主轴/航向语义无漂移。
- [ ] 思路连贯；渲染总页数 ≤45（超页先砍重复，不砍实施方式必要披露）。
- [ ] 图注缩写有中文全称。

## 六、反面清单（真实踩过的坑，提交前逐条排查）

- **在发明内容或实施例中再写一遍正式权利要求**（出现「1.一种…其特征在于」「根据权利要求N所述」）→ 只保留权利要求书那一份。  
  含装配错误：`title` 写在 `claim` 前导致说明书吞权项——见 `lessons-learned.md` L1。
- **单独增设「有益效果」一级标题** → 参考模板把优点写在发明内容末尾「显著优点为：（1）…」。
- **照搬模板技术内容** → 只借版式与行文骨架。
- **为压到 10 条而删除创新点** → 合并进从属子特征。
- **为控页把具体实施方式压成提纲** → 保留「进一步地/具体地」可实施披露（L2）。
- **公式缺「其中…为…」**（L3）；**英文术语未中文化**（L4）；**分支只写一半**（L5）。
- **术语漂移**；**发明内容灌入实施例级数值**导致超页。
- **草稿痕迹 / 步骤编号混乱 / 示例自相矛盾 / 半角标点 / 段过长 / 捏造参数**。
- **漏掉摘要附图节**（参考模板五节时）。
- **AI 黑盒**无输入—输出与场景关联（局令84号 / L8）。

完整列表见 `references/lessons-learned.md`。
